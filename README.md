# @tanvir143/ica

### Local Instagram private API client • FCA-compatible InstaBot adapter • Cookie/AppState auth • MQTT realtime

> **Unofficial/private API:** this package uses Instagram private endpoints. Those endpoints can change without notice. Use only sessions/accounts you are authorized to use and follow Instagram's terms and applicable rules.

## About

`@tanvir143/ica` is the Tanvir143 ICA package adapted from the supplied `ig-chat-api` login approach and the existing `ica-tanvir143` codebase.

The important change is the authentication path:

1. Import the supplied cookie/AppState data into a local cookie jar.
2. Use a browser-style User-Agent during session validation.
3. Validate with Instagram's plain `current_user` endpoint (without the failing legacy `edit=true` query).
4. If that endpoint returns an application-level error, fall back to a normal Instagram web-session check using the same cookie jar.
5. Preserve explicit login-required, logged-out and checkpoint errors instead of hiding them.
6. Continue using the local ICA client and MQTT connection after authentication.

No remote ICA/RPC server is required.

## Installation

```bash
npm install @tanvir143/ica
```

The package is public and scoped, so the install command above is the only package dependency needed for the ICA itself.

## FCA/InstaBot login

```js
const login = require('@tanvir143/ica');

login({ appState }, (err, api) => {
  if (err) return console.error('Login failed:', err);

  console.log('Logged in user ID:', api.getCurrentUserID());

  api.listenMqtt((err, event) => {
    if (err) return console.error('MQTT error:', err);
    console.log('Instagram event:', event);
  });
});
```

Promise style is also supported:

```js
const login = require('@tanvir143/ica');

const api = await login({ appState });
console.log(api.getCurrentUserID());
```

## Accepted authentication input

The compatibility login accepts:

- AppState/cookie arrays
- `{ appState: [...] }`
- `{ cookies: [...] }`
- JSON cookie strings
- cookie-header strings such as `sessionid=...; ds_user_id=...; csrftoken=...`
- Netscape cookie text
- `{ cookieFile: './account.json' }`
- username/password through the underlying client where supported

For cookie/AppState login, the bot should provide the authenticated session cookies it is authorized to use. Do not publish real session cookies, passwords or tokens.

### Cookie header example

```js
login({
  cookies: 'sessionid=YOUR_SESSION; ds_user_id=YOUR_USER_ID; csrftoken=YOUR_CSRF'
}, callback);
```

## Login method used in this release

The supplied `ig-chat-api` 1.0.0 reference uses a cookie jar, browser-style User-Agent and a web fallback when its API validation fails. This release keeps that useful part of the method while fitting it into the existing ICA architecture.

### Primary validation

```text
/api/v1/accounts/current_user/
```

The old failing request:

```text
/api/v1/accounts/current_user/?edit=true
```

is no longer generated by `AccountRepository.currentUser()`.

### Fallback validation

If the primary endpoint returns an application-level error, ICA checks:

```text
https://www.instagram.com/
```

with the same cookie jar and a browser-style User-Agent. Explicit `login_required`, `user_has_logged_out` and checkpoint errors are not swallowed.

This fallback does **not** bypass Instagram checkpoints, two-factor authentication or other security controls.

## Using with Tanvir143_igBot

Change the bot dependency to:

```json
{
  "dependencies": {
    "@tanvir143/ica": "1.0.0"
  }
}
```

Then the bot should load:

```js
const login = require('@tanvir143/ica');
```

The ICA runs locally inside the bot process. No `/rpc` URL, remote ICA server or remote transport is required.

## Testing scope

Automated checks cover:

- package metadata and scoped package name
- generated distribution files
- compatibility method surface
- response-folder upload limits
- JavaScript/TypeScript syntax and source-level login checks
- the absence of the legacy `current_user/?edit=true` request in the login path

A live Instagram login is intentionally not performed in CI because it would require a real account session/cookie.

## Security

Never commit:

```text
account.txt
AppState.json
cookies.json
.env
Instagram passwords
sessionid values
csrftoken values
private API tokens
```

If a session cookie is exposed publicly, revoke that session and create a new one.
